# Roadmap — scipion-em

**Status: draft, pending review with Yunior (repo co-owner).** Seeded from a rough team Google Doc plus findings surfaced while doing the test/CI/Python-3.8-3.12 work on this repo (2026-08-04). Treat as a starting point, not a committed plan.

## This repo specifically

- **[Done, 2026-08-04] `pwem/tests/workflows/*`'s dependency on external plugins - audited and resolved where a substitute existed.** Went through every workflow test class and classified each as either generic core-framework behavior exercised through a plugin protocol as "something to run" (replaced with a plugin-free equivalent) or genuinely plugin-specific (left alone, still excluded from hermetic CI). Net result: +10 tests now genuinely passing hermetically, +2 more collected as honest (dataset-gated) skips instead of being invisible, 3 files deleted (`test_workflow_mixed.py`, `test_workflow_mixed_large.py`, `test_workflow_initialvolume.py` - 100% real multi-plugin integration/convergence testing, no extractable core logic). Details:
  - `test_parallel_gpu_queue.py` → moved to `pwem/tests/protocols/test_parallel_queue.py`, Relion/Xmipp swapped for a new plugin-free `ProtTestQueue` (`pwem/protocols/protocol_tests.py`). The `useQueue=True` variants (`TestQueueALL`/`TestQueueSmall`/`TestQueueSteps`) were dropped instead - they need a real HPC scheduler (`qsub`/`qstat`) configured in `hosts.conf`, a separate problem from plugin dependency. **New follow-up task**: build a local fake-queue `SUBMIT_COMMAND` (a plain script instead of a real PBS/SLURM call) so this can be tested hermetically too.
  - `ProtExtractCoords`'s coordinate-rescaling logic now covered by a mock-based unit test (`pwem/tests/protocols/test_protocol_extract_coorinates.py`), reusing the existing `pwem/tests/utils.py` mock pattern - no plugin, no protocol execution needed. `test_workflow_xmipp.py`'s duplicate check removed; its `applyShifts=True` variant (a separate, more involved `getShifts()` code path) was left as still-uncovered, noted here as a smaller follow-up.
  - Tilt-pair import/pointer coverage: turned out to already exist, unrelated to this effort - `pwem/tests/protocols/test_protocols_import_coords.py::TestImportCoordinatesPairs` covers the same `ProtImportMicrographsTiltPairs`/`ProtImportCoordinates` setup `test_workflow_xmipp_rct.py`/`test_workflow_xmipp_assignment_tiltpairs.py` use, same `rct` dataset. No new file needed, just annotated.
  - CTF-consensus streaming mechanism: **not resolved**, real blocker found. `ProtCreateStreamData`'s only from-scratch mode (`SET_OF_RANDOM_MICROGRAPHS`) itself depends on xmipp3 (`createRandomMicStep` calls `xmipp_transform_filter`) - not the plugin-free synthetic-data generator it looks like. Every other mode needs a real pre-existing input Set. **New follow-up task**: either fix `ProtCreateStreamData`'s random-mode to not need xmipp3, or build a minimal from-scratch synthetic-micrograph generator elsewhere, to unblock a genuine pwem-specific streaming test.
  - `TestImportData`/`TestImportBase` (Chimera/Coot/Refmac/EMRinger/Molprobity tests' shared import setup) moved to `pwem/tests/protocols/test_import_volume_and_pdb.py` with 2 new smoke tests - currently skipped (needs `model_building_tutorial` dataset), will start passing once that's synced.
- **Audit dataset-dependent tests.** For the ~103 tests currently skipped for needing real EM data: download the datasets, look at what the referenced files actually contain and how each test uses them, and evaluate case-by-case whether a small synthetic fixture could replace the real dataset. (Some of the newly-relocated tests above, e.g. `test_import_volume_and_pdb.py`, would become real passing coverage the moment this happens for `model_building_tutorial`/`rct`.)
- Consider a real-dataset-sync CI job (currently deferred - network dependency on an external CNB-hosted server, slow/heavy) if the above audit concludes some tests are worth running for real in CI.
- `pwem/viewers/viewers_data.py:266,304`'s FIXME about the xmipp3 coupling — same underlying "core depends on a specific plugin" pattern as the workflows-tests audit above, not yet addressed.
- **Core-code-locked-to-one-plugin audit (2026-08-27), full findings in `.ai/tech-debt.md`.** Triggered by the `ProtCreateStreamData` fix above raising the question more broadly. Biggest finding, not yet fixed: `pwem/emlib/image/image_handler.py`'s `ImageHandler` - pwem's central image class - has 8 methods (`createCircularMask`, `rotateVolume`, addNoise, resize, threshold ×2, one more, downsample) that are thin wrappers shelling out to xmipp3 (7) or eman2 (1) binaries; each needs a real numpy/emlib-native reimplementation to fix, not a one-line swap - substantial follow-up work, not started. `pwem/protocols/parallel.py` (`ProtTestParallel`, dead legacy code with the same anti-pattern) **[Done, 2026-08-27]** - deleted, fully superseded by `ProtTestQueue`. `pwem/viewers/showj.py:302`'s `xmipp3.Plugin.getEnviron()` for launching the Java "showj" viewer - not yet assessed (may be legitimate if showj itself is Xmipp-authored software).
- **New finding, needs a real fix (not urgent, but real)**: `pwem/tests/conftest.py`'s session-teardown (`shutil.rmtree` on the shared `SCIPION_HOME`) isn't safe against two concurrent pytest invocations against this repo - one finishing early can wipe the directory out from under a still-running one, causing cascading `SystemExit: Missing file .../hosts.conf` failures. Only matters if something runs pytest concurrently against this repo (rare, but happened once during this session's own work). Consider a per-session unique `SCIPION_HOME` subdirectory instead of a fixed shared path, if this becomes a recurring problem.

## Ecosystem-wide (applies to all 5 repos, not just this one)

- **Branch/release cleanup**: drop the redundant `master` branch, rename `devel` → `main`, replace push-triggered publish with a manual `workflow_dispatch` release gated by a protected GitHub deployment environment. `I2PC/scipion-em-xmipp`'s `.github/workflows/release.yml` is a concrete reference.
- **Remove Tkinter entirely** once ScipionAPI + ScipionWeb fully replace it (ScipionWeb replaces both the legacy Tkinter GUI and an intermediate NiceGUI attempt).
- **Convert buildbot to a GitHub Actions self-hosted runner.**
- **Set up a dependency manager (Renovate)** across all 5 repos.
