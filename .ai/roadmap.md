# Roadmap — scipion-em

**Status: draft, pending review with Yunior (repo co-owner).** Seeded from a rough team Google Doc plus findings surfaced while doing the test/CI/Python-3.8-3.12 work on this repo (2026-08-04). Treat as a starting point, not a committed plan.

## This repo specifically

- **[Done, 2026-08-04] `pwem/tests/workflows/*`'s dependency on external plugins - audited and resolved where a substitute existed.** Went through every workflow test class and classified each as either generic core-framework behavior exercised through a plugin protocol as "something to run" (replaced with a plugin-free equivalent) or genuinely plugin-specific (left alone, still excluded from hermetic CI). Net result: +10 tests now genuinely passing hermetically, +2 more collected as honest (dataset-gated) skips instead of being invisible, 3 files deleted (`test_workflow_mixed.py`, `test_workflow_mixed_large.py`, `test_workflow_initialvolume.py` - 100% real multi-plugin integration/convergence testing, no extractable core logic). Details:
  - `test_parallel_gpu_queue.py` → moved to `pwem/tests/protocols/test_parallel_queue.py`, Relion/Xmipp swapped for a new plugin-free `ProtTestQueue` (`pwem/protocols/protocol_tests.py`). The `useQueue=True` variants (`TestQueueALL`/`TestQueueSmall`/`TestQueueSteps`) were dropped instead - they need a real HPC scheduler (`qsub`/`qstat`) configured in `hosts.conf`, a separate problem from plugin dependency. **New follow-up task**: build a local fake-queue `SUBMIT_COMMAND` (a plain script instead of a real PBS/SLURM call) so this can be tested hermetically too.
  - `ProtExtractCoords`'s coordinate-rescaling logic now covered by a mock-based unit test (`pwem/tests/protocols/test_protocol_extract_coorinates.py`), reusing the existing `pwem/tests/utils.py` mock pattern - no plugin, no protocol execution needed. `test_workflow_xmipp.py`'s duplicate check removed; its `applyShifts=True` variant (a separate, more involved `getShifts()` code path) was left as still-uncovered, noted here as a smaller follow-up.

- **Core-code-locked-to-one-plugin audit (2026-08-27), full findings in `.ai/tech-debt.md`.** Triggered by the `ProtCreateStreamData` fix above raising the question more broadly. Full triage done:
  - `pwem/protocols/parallel.py` (`ProtTestParallel`) **[Done, 2026-08-27]** - deleted, dead code fully superseded by `ProtTestQueue`.
  - `pwem/protocols/protocol_align_movies.py`'s `ProtAlignMovies.computeThumbnail()` **[Done, 2026-08-27]** - reimplemented in-process (numpy mean-shrink + percentile contrast stretch, written via PIL), no longer needs eman2. Also removed a dead, unused duplicate of `ImageHandler`'s xmipp helper this file had copy-pasted in.
  - `pwem/viewers/showj.py:302` and `pwem/viewers/viewers_data.py:266,304` **[Investigated 2026-08-27, legitimate, not actionable independently]** - both feed genuinely Xmipp-authored Java tools (the "showj" viewer, the coordinate-picker GUIs) - there's no plugin-agnostic core operation being needlessly locked down here, the tool being launched really is Xmipp's own software. Only fixable by replacing those Java tools entirely, which is what the ecosystem-wide "Remove Tkinter" item below already covers - not worth tracking as a separate task.
  - `pwem/protocols/protocol_import/*.py`, `pwem/cmd/convert.py`, `pwem/utils.py:67`'s `runProgram` **[Investigated 2026-08-27, confirmed legitimate]** - format-specific import dispatchers gated behind the user's explicit format choice, or (for `runProgram`) a symmetric multi-plugin dispatcher, not a lock-in. No action needed.
  - **`pwem/emlib/image/image_handler.py`'s `ImageHandler` - the one real piece of unfinished work, and the biggest.** pwem's central image class has **6 methods** (not 8 as first estimated - re-read confirmed some call sites share a method) still shelling out to xmipp3 or eman2: `createCircularMask`, `rotateVolume`, `addNoise`, `truncateMask` (2 xmipp calls: threshold, optional resize), `computeThumbnail` (eman2, different from the now-fixed `ProtAlignMovies` one - uses Fourier-domain shrink, not mean-shrink), `scaleFourier`/downsample (already has its own `# TODO: Avoid using xmipp program for this` in the code). **Not started yet** - see the phased plan below.

  **Plan for `ImageHandler`, once picked up** (ordered easiest/lowest-risk first, each phase independently shippable and testable the same way `computeThumbnail`/`ProtCreateStreamData` were - a real hermetic test proving the method still does the right thing, not just that it runs):
  1. **`rotateVolume` and `truncateMask`'s resize step - likely near-free, not new algorithms.** `emlib.Image` already exposes native (non-plugin) methods that do the same job in-process: `applyTransforMatScipion(matrixAsList)` (already used elsewhere in this very file's `convert()`) for `rotateVolume`'s matrix-rotation case, and `.scale(x, y, z, setDimensions)` (already used in this file's own `scaleSplines`, itself already plugin-free) for `truncateMask`'s optional `--dim` resize. Confirm both produce equivalent results to the xmipp CLI calls being replaced, then just wire them in - this is re-routing to an already-existing native method, not writing new image-processing code.
  2. **`addNoise` and `truncateMask`'s threshold calls - trivial numpy.** Gaussian noise addition (`arr + np.random.normal(avg, std, arr.shape)`) and value clamping (`np.clip`) are one-liners with well-defined, unambiguous semantics - lowest risk in the whole list.
  3. **`createCircularMask` - small, well-defined numpy.** Build a circular boolean/float mask via a distance-from-center comparison (`np.ogrid` or equivalent) sized to match `refImage`'s dimensions - no external dependency, a few lines.
  4. **`scaleFourier` (aka the `# TODO` downsample) and `ImageHandler.computeThumbnail` - moderate, same underlying building block.** Both are Fourier-domain crop-based resampling (downsample by cropping high frequencies in `numpy.fft.fft2`/`ifft2`, then for the thumbnail case also contrast-stretch to a displayable range, the same percentile-normalize step `ProtAlignMovies.computeThumbnail`'s fix already uses). Worth implementing the Fourier-crop step once as a shared internal helper both call, rather than duplicating it - avoiding the exact duplication (`ImageHandler.computeThumbnail` vs `ProtAlignMovies.computeThumbnail`, mean-shrink vs Fourier-shrink) already found once during this audit.
  - **Cross-cutting for all of the above**: verify each replacement against real xmipp-produced output (spot-check that the new numpy path and the old `xmipp_transform_*`/`e2proc2d.py` path agree closely on the same input, similar to how `ProtCreateStreamData`'s `emlib.applyCTF` fix was verified against real image statistics before/after) - not just "the function runs and returns something."
- **New finding, needs a real fix (not urgent, but real)**: `pwem/tests/conftest.py`'s session-teardown (`shutil.rmtree` on the shared `SCIPION_HOME`) isn't safe against two concurrent pytest invocations against this repo - one finishing early can wipe the directory out from under a still-running one, causing cascading `SystemExit: Missing file .../hosts.conf` failures. Only matters if something runs pytest concurrently against this repo (rare, but happened once during this session's own work). Consider a per-session unique `SCIPION_HOME` subdirectory instead of a fixed shared path, if this becomes a recurring problem.

## Ecosystem-wide (applies to all 5 repos, not just this one)

- **Branch/release cleanup**: drop the redundant `master` branch, rename `devel` → `main`, replace push-triggered publish with a manual `workflow_dispatch` release gated by a protected GitHub deployment environment. `I2PC/scipion-em-xmipp`'s `.github/workflows/release.yml` is a concrete reference.
- **Remove Tkinter entirely** once ScipionAPI + ScipionWeb fully replace it (ScipionWeb replaces both the legacy Tkinter GUI and an intermediate NiceGUI attempt).
- **Convert buildbot to a GitHub Actions self-hosted runner.**
- **Set up a dependency manager (Renovate)** across all 5 repos.
